# 原文锚点标注台（Anchor Annotation Console）

粘贴原文 → 拖选片段 → 添加标签与备注；之后即使修改原文，标注也会按照确定性的锚点规则重新定位，
**无法确定去向的标注一律进入「待处理」列表，绝不静默误绑**。还可配置若干**互斥标签对**，自动审阅
区间交叠的标签冲突（支持忽略：区间重定位不失效，标签变化后自动重新出现）；并提供**标签覆盖审计**：
选择一组应共同覆盖全文的标签，自动列出覆盖缺口与多层重叠，点击即可定位。另有**快照对比**：
把当前标注集保存为唯一基线，随时对比新增 / 删除 / 修改并逐项审阅。以及**抽样复核**：为一个或多个
标签填写抽样数并输入种子，系统仅从已绑定标注中按 `SHA-256(种子 + 标注 ID)` 生成稳定顺序、逐轮
贪心抽中最能补足配额的标注；抽中项可标记通过或退回并填写复核备注，结论绑定标注 ID 与内容签名，
内容变化自动失效。另有**训练集划分导出**：仅使用已绑定标注，把区间有字符交集的标注（含传递关系）
归入同一连通组整组划分，填写 train/validation/test 百分比与种子后按
`SHA-256(种子 + 组内标注 ID 排序拼接)` 稳定排序、贪心分配，分别下载三个 JSONL，待处理标注排除不导出。
纯前端实现，React + TypeScript + Vite，数据保存在浏览器本地，可导出包含原文、
引文、上下文、状态、互斥规则、覆盖审计标签、忽略记录、基线快照、已审记录、抽样配置与复核结论的 JSON。

## 一键启动（Docker）

只需一条命令（需本机已安装 Docker；首次会构建镜像）：

```bash
docker compose up --build -d
```

启动后用浏览器访问：**<http://localhost:8080>**（容器内 Nginx 监听 80，映射到宿主机 **8080** 端口）

停止与清理：

```bash
docker compose down          # 停止
docker compose down -v       # 停止并清理（本应用不挂载数据卷，数据仅存在浏览器中）
```

> 8080 端口被占用时，修改 `docker-compose.yml` 中的 `"8080:80"`，例如 `"9000:80"`。

## 快速使用

1. 点击左上角「粘贴原文」，贴入全文（可同时修改标题）后「完成编辑」。
2. 在原文中**拖选任意片段**，在弹出表单里添加标签与备注；同一区间可保留多条标注。
3. 需要修改原文时随时「粘贴 / 编辑原文」：标注按锚点规则自动重定位，无法确定去向的进入**待处理**，
   点「重新选择片段」拖选即可重新绑定。
4. 侧栏「冲突审阅 → 配置互斥对」设置互斥标签（如 `正面 ⇄ 反面`），区间交叠的冲突会自动列出。
5. 侧栏「标签覆盖审计」中点选一组应共同覆盖全文的标签：**红色虚框为缺口、橙色虚框为重叠**，
   点击侧栏结果可滚动定位；标签、标注、原文或标签名变化后结果实时重算。
6. 侧栏「快照对比 → 保存当前为基线」后，任何标注变动都会按新增 / 删除 / 修改列出，
   逐项「标记已审」跟踪审阅进度。
7. 侧栏「抽样复核」中为一个或多个标签填写**抽样数**、输入**种子**后「生成抽样队列」：
   按稳定顺序抽中的标注逐张卡片复核，可「通过 / 退回」并填写备注；每个标签展示目标数、实际数与缺口。
8. 侧栏「训练集划分导出」中填写 **train / validation / test 百分比（合计须为 100）** 与**种子**，
   「计算划分」后查看各集合组数、标注数与实际占比，并分别**下载 JSONL**；待处理标注自动排除并显示排除数。
9. 数据自动保存在本浏览器；换机器或备份时用「导出 JSON / 导入 JSON」。

## 功能说明

- **拖选标注**：在原文上拖选任意片段，弹出表单填写标签（回车/逗号添加，支持历史标签补全）与备注。
- **同一区间多条标注**：多个标注区间可重叠共存，高亮颜色按叠加混合；点击重叠处可查看该区间的全部标注。
- **编辑原文后自动重定位**：点击「粘贴 / 编辑原文」修改并保存，全部标注按下列优先级重新定位。
- **待处理列表**：最高分并列、评分为 0 或引文消失的标注进入待处理；点「重新选择片段」后在原文中拖选，
  确认即可完成绑定，引文与上下文快照同步更新。
- **定位 / 编辑 / 删除**：侧栏与弹层内均可操作；「定位」会滚动并高亮原文中的对应片段。
- **冲突审阅**：在侧栏「冲突审阅」中配置若干互斥标签对（如 `正面 ⇄ 反面`）。系统只检测
  **已绑定**标注：两条标注区间有**至少 1 个字符交集**、且标签分别命中同一互斥对时归入同一冲突项；
  同一对标注即使命中多条规则也只显示一次，并列出全部命中规则与**交叠原文**。面板按交叠起点排序，
  支持定位双方、定位交叠处、编辑任一标注，或把该冲突标记为**忽略**（忽略项折叠在底部，可随时取消）。
  - 忽略签名为「两个标注 ID + 命中规则 ID 集合」，**不含区间**：编辑原文导致区间重定位后忽略不失效；
    标签或规则变化使命中规则集合改变时，冲突会**自动重新出现**。
  - 冲突交叠处在原文中以红色波浪下划线标出；顶栏「冲突审阅」按钮与页脚显示待审阅数量。
- **标签覆盖审计**：在侧栏「标签覆盖审计」中点选一组**应共同覆盖全文**的标签（再点一次取消）。
  系统只纳入**已绑定**、区间非空且**命中所选标签**的标注，按半开区间 `[start,end)` 扫描全文：
  - 覆盖数为 **0** 的连续区间记为**缺口**，大于 **1** 的记为**重叠**；待处理标注与空区间忽略；
  - 端点相接（如 `[0,10)` 与 `[10,20)`）不算重叠、也不留缺口；
  - **相邻且类型与参与标注集合相同的结果自动合并**（例如缺口被一个未参与审计的标注区间隔开、
    或重叠被一个未命中标签的标注端点分段，都会并回一条）；
  - 侧栏按起点列出每条问题的类型、原文摘录、位置/字数；重叠卡片额外列出**涉及的每条标注**
    （引文、标签，可单独定位或编辑）。点击结果或摘录即在原文中滚动并高亮整条范围：
    缺口以红色虚框标出，重叠以橙色虚框标出；
  - 审计结果在**标签选择、标注新增/编辑/删除/重新绑定、原文编辑后重定位、标签重命名**后自动重算；
    标签重命名时所选的覆盖标签同步精确替换（保序去重）。顶栏「覆盖审计」按钮可快速跳到该分区，
    存在问题时显示总数。
- **标签重命名**：侧栏「标签管理」区点击「标签重命名」，从当前标签（含仅被互斥规则引用的标签）中选择
  **源标签**、填写**目标标签**，提交前先看到**预览**：受影响标注数、受影响互斥规则数、将被合并 / 删除的
  规则数、将被清理的忽略记录数，并可展开查看每条标注的标签前后变化（目标标签已存在时会标「去重」）与每条
  规则的去向。**取消预览不改动任何数据**；确认后在一次状态更新中原子完成：
  - 每条标注内精确替换源标签；因替换出现重名时只保留靠前的一个，**其余标签顺序不变**（bound / pending 标注同等处理）；
  - 互斥规则的两端同步替换；替换后两侧相同的**自互斥规则直接删除**；
  - 替换后形成的无序重复标签对（与方向无关）按 `createdAt` 升序、再按规则 `id` 字典序**保留最早一条**，
    其余规则并入保留规则——被合并 / 删除规则的 ID 会映射到保留规则的 ID；
  - 忽略记录先按上述映射改写规则 ID，再重新核对冲突签名：仍能对应当前冲突的保留（忽略状态延续），
    已无法对应（规则全部消失、标注进入 pending / 被删除、标签替换后不再命中等）的自动清理；
    多条记录映射到同一签名时保留最早一条。
- **快照对比**：侧栏「快照对比」中把当前标注集保存为**唯一基线**（再次保存即重建，旧基线与全部已审
  记录一并清空）。之后系统按**稳定标注 ID** 把基线与当前数据的差异归为三类：
  - **新增**：仅当前存在的标注；**删除**：仅基线存在的标注（卡片展示**基线引文**与当时的区间、
    标签、备注）；**修改**：两侧都存在但内容不同的标注——**同一标注只生成一项**，并逐字段列出
    **区间/绑定状态、引文、标签、备注**的前后值；
  - 差异列表**按原文位置排序**（当前仍绑定的取当前区间，否则取基线区间），可按类型筛选；
    当前仍已绑定的项可**定位**到原文；
  - 每项可**标记已审**，已审状态以「**标注 ID + 差异内容签名**」持久化：内容再次变化 → 签名改变，
    该项重新出现为未审；恢复成基线 → 差异项消失、对应已审记录自动移除；**重建基线清空全部已审**；
  - 顶栏「快照对比」按钮与页脚显示待审差异数；基线与已审记录随本地保存与 JSON 导入导出，
    旧版导出文件缺少这些字段时按空处理。
- **抽样复核**：侧栏「抽样复核」中为一个或多个标签填写**抽样数**（配额）并输入任意字符串作为
  **种子**（也可一键随机生成），「生成抽样队列」后系统**仅从已绑定标注**中取样（待处理标注不参与）：
  - 候选为全部已绑定、且命中至少一个目标标签的标注；为每个候选计算
    **`SHA-256(种子 + 标注 ID)`** 十六进制摘要；
  - 随后**逐轮贪心**：每轮在尚未入选、且仍能补足至少一个尚缺标签配额的候选中，优先选择
    **能补足最多尚缺标签**的标注（一条同时携带多个目标标签的标注会优先入选并同时计入这些标签），
    **同数时按哈希字典序、再按标注 ID 字典序**取第一，直至所有标签配额满足或候选耗尽；
  - 因此**同一份配置（种子 + 标签配额）与同一份标注集必然得到同一个队列**，与标注在界面中的顺序无关；
  - 队列上方逐标签展示**目标数、实际数与缺口**：候选耗尽后仍不足的配额记为缺口；
    一条标注覆盖多个标签时，某标签的实际数可能超过其目标（超额）；
  - 每张抽中卡片可点「定位」跳到原文，并可填写**复核备注**后标记**通过 / 退回**（再次点击可取消）；
    结论以「**标注 ID + 标注内容签名**」持久化——区间/绑定状态、引文、标签、备注任一变化都会使
    签名改变，该结论**自动失效**、抽中项回到待复核；
  - 顶栏「抽样复核」按钮与页脚显示待复核抽中项数；标签重命名时抽样配置中的标签同步替换、
    重复标签的配额相加；配置与结论随本地保存与 JSON 导入导出，旧版导出文件缺少这些字段时按空处理。
- **训练集划分导出**：侧栏「训练集划分导出」中填写 **train / validation / test 三个整数百分比
  （每个 0-100，合计须恰好为 100）** 与任意字符串**种子**（可一键随机），「计算划分」后系统
  **仅使用已绑定标注**（待处理标注一律排除并显示排除数，不导出）：
  - **连通分组**：两条标注区间只要有**至少 1 个字符交集**（半开区间 `[start,end)` 下
    `start < other.end && other.start < end`；端点相接不算、空区间各自成组）即归入同一组，
    交集按**传递闭包**合并。**任何一组都是不可拆分的整体**，只能完整进入一个数据集；
  - **稳定排序**：每组计算 **`SHA-256(种子 + 组内标注 ID 排序后拼接)`** 十六进制摘要，
    全部组按摘要字典序排列；
  - **贪心分配**：按排序依次把每个组放入**当前相对目标缺口最大**的集合——集合 i 的相对缺口为
    `(目标百分比 − 当前组数占比 × 100) / 目标百分比`（比较交叉相乘化为整数，无浮点误差），
    缺口完全相同按 **train、validation、test** 的固定顺序决胜；目标为 0 的集合永不入选。
    因此**同一份标注集 + 相同百分比与种子必然得到同一份划分**；
  - 面板分别展示三个集合的**组数、标注数与实际占比**（标注数口径的实际百分比，并附注按组数的百分比；
    因组不可拆分且各组标注数不同，实际占比可能与目标有偏差），并列出每组明细；
  - 每个集合可单独**下载 JSONL**（空集合按钮禁用）：**每个连通组一行**，每行包含
    **文档标题、原文、集合名（train / validation / test）** 以及组内标注的
    **ID、区间、引文、标签和备注**。划分参数不写入本地存档、也不影响「导入 / 导出 JSON」。
- **本地保存**：每次改动自动写入 `localStorage`，刷新与重开浏览器不丢失。
- **导入 / 导出 JSON**：导出包含原文、每条标注的引文、区间、标签、备注、绑定上下文、状态与重定位诊断，
  以及互斥标签对配置、冲突忽略记录、覆盖审计所选标签、基线快照与快照已审记录、抽样配置与复核结论；
  导出文件可再次导入恢复。旧版本导出的 JSON（无冲突 / 覆盖审计 / 快照 / 抽样字段）可无损导入。
- **新建文档**：清空当前文档重新开始（操作前提示导出备份）。

## 重定位算法

设标注保存时的引文为 `quote`，旧区间为 `[start, end)`，并记录区间两侧各 50 字的上下文。
编辑得到新原文后，按以下顺序处理：

1. **旧位置前后 200 字内精确匹配**：在新原文 `[start-200, end+200]` 窗口（自动截断到全文边界）中
   搜索 `quote`。窗口内**恰好一处**命中 → 绑定该处。
2. **全文唯一匹配**：窗口内无命中（或不唯一）时，若 `quote` 在全文中只出现一次 → 绑定该处。
3. **前后文相同字符数评分**：全文存在多处候选时，对每个候选位置评分：
   - 左侧：从候选起点向左，与旧上文末尾逐字符连续相同的字符数；
   - 右侧：从候选终点向右，与旧下文开头逐字符连续相同的字符数；
   - 总分 = 左 + 右。取得分最高者绑定。

以下情况**不自动绑定，进入待处理列表**（并在标注上注明原因）：

- 全文找不到 `quote`（`not-found`）；
- 最高分被多个候选并列取得（`tie`）；
- 最高分为 0（`zero-score`，说明候选周围的上下文与旧文完全不同）。

每次重定位所走的策略、分数与旧位置都会写入标注的 `lastRelocation`，侧栏与导出 JSON 中可见。
手动重新绑定后，引文与两侧上下文快照更新为新位置的内容，后续编辑继续据此重定位。

```jsonc
      "quote": "被标注的原文片段",

      "tags": ["标签"],
      "position": { "start": 12, "end": 28 },   // pending 时为 null
      "context": { "before": "前 50 字", "after": "后 50 字" },
      "pendingReason": null,                     // pending 时为中文原因
      "lastRelocation": {                        // 经历过编辑重定位时存在
        "reason": "context-score",               // local-exact | unique | context-score | failed
        "score": 17,
        "oldStart": 10, "oldEnd": 26,
        "sourceFingerprint": "…", "timestamp": 0
      },
      "createdAt": "...", "updatedAt": "..."
    }
  ]
}
```

## 训练集划分 JSONL 结构

三个文件（`..._train.jsonl` / `..._validation.jsonl` / `..._test.jsonl`）均为 UTF-8 编码的 JSONL，
**每个连通组占一行**（每行一个独立 JSON 对象），行序为组的稳定哈希顺序：

```jsonc
{
  "title": "文档标题",
  "text": "文档原文（每行重复，方便脱离上下文直接消费）",
  "dataset": "train",                    // train | validation | test
  "group": {
    "annotationIds": ["a_1", "a_2"],     // 组内全部标注 ID，字典序
    "annotations": [                     // 组内标注（整组同属一个数据集，绝不拆分）
      {
        "id": "a_1",
        "position": { "start": 12, "end": 28 },
        "quote": "被标注的原文片段",
        "tags": ["标签"],
        "note": "备注"
      }
    ]
  }
}
```

待处理（pending）标注不参与划分、不出现在任何文件中；面板会显示其排除数。

## 数据与隐私

- 没有后端，所有数据仅保存在当前浏览器的 `localStorage`（键名 `anchor-annotation-console:v1`）。
- 清除浏览器站点数据会删除标注，请先用「导出 JSON」备份；导出文件可随时「导入 JSON」恢复。
- Docker 镜像仅托管构建后的静态文件（Nginx），不在容器或服务端保存任何数据。
